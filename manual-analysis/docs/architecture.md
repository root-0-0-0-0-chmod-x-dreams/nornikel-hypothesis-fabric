# Manual Analysis — Архитектура

## Обзор

Сервис преобразует Excel-таблицы с данными о хвостах флотации в структурированный формат анализа потерь по шаблону `tailings_analysis_input.csv`.

## Схема

```
Excel (.xlsx) → Parser (deterministic)  ──→ AnalysisResult
              → LLM Analyzer (if avail) ──→ (CSV rows)

Если LLM доступен — сначала пробуем LLM.
Если LLM недоступен или вернул ошибку — fallback на детерминированный парсер.
```

## Компоненты

### 1. Parser (`parser.py`)
Детерминированный анализатор Excel. Алгоритм:
1. Определяет колонки по заголовкам (металл 28/29, итого)
2. Извлекает секции:
   - **Минералогия**: силикаты, валлериит, примеси в пирротине, пирит
   - **Фракции**: шламы (-10 мкм), крупные сростки (+74 мкм)
   - **Автоматизация**: ~5% от флотационных потерь (оценка)

### 2. LLM Analyzer (`llm_analyzer.py`)
Отправляет упрощённое представление Excel в LLM-сервис для интеллектуального анализа. Промпт содержит:
- Данные Excel (первые 200 строк)
- Шаблон CSV
- Правила маппинга категорий
- Строгое требование JSON-ответа

### 3. Router (`router.py`)
- `GET /api/v1/health` — статус + доступность LLM
- `POST /api/v1/analyze` — анализ Excel-файла
  - Параметр `use_llm` (default: true) — использовать ли LLM

### 4. Модель результата (`models.py`)
```python
AnalysisRow:
    Анализ: str           # Минералогия | Фракции | Автоматизация
    Статья_Потерь: str    # описание статьи потерь
    Металл_1_т: float     # потери металла 1, тонн
    Металл_2_т: float     # потери металла 2, тонн
    Доп_Инфо: str         # причина/характеристика
```

## Поток обработки

```
1. POST /analyze (xlsx-файл)
2. Сохранение во временный файл
3. Если use_llm=true и LLM доступен:
   a. LLM: подготовка данных → запрос → парсинг JSON → AnalysisRow[]
   b. При ошибке или пустом результате → fallback
4. Детерминированный парсер: parse_excel() → AnalysisRow[]
5. AnalysisResult → JSON-ответ
```
