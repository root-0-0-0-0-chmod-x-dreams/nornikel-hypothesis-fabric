Фабрика гипотез - интеллектуальная система генерации научно-исследовательских гипотез для НИИ и промышленных лабораторий (материаловедение, металлургия).

ПРОБЛЕМА

На старте R&D-проектов гипотезы формируются вручную, опираясь на опыт отдельных экспертов. Это порождает пять проблем: 
    Субъективность - идеи зависят от конкретных людей, процесс невоспроизводим
    Слабая связь с бизнесом - нет привязки к KPI и экономическому эффекту
    Отсутствие единого формата оценки - нельзя сравнить гипотезы по новизне, рискам и ресурсам; (5) медленный старт - недели уходят на формулировку и согласование направлений.
    Мёртвые архивы - накопленные отчёты, лабораторные журналы и патенты не используются для генерации новых идей

РЕШЕНИЕ

Система принимает на вход:
    Описание технологической проблемы (например, «повысить жаропрочность сплава Х на 15% при 800°С»)
    Ограничения (доступное сырьё, бюджет, оборудование, нормативы) 
    Документы (научные статьи, патенты, внутренние отчёты, URL). 

На выходе формирует структурированный список проверяемых гипотез. По каждой гипотезе предоставляется: 
    Научное обоснование с указанием механизма влияния
    Сссылки на релевантные источники с цитированием
    Оценка новизны (high/medium/low) относительно известных решений
    Карта рисков (технические и экономические)
    Ожидаемая ценность с привязкой к целевому KPI. 

Для каждой гипотезы опционально генерируется дорожная карта проверки - последовательность экспериментов с оценкой необходимых ресурсов, длительности каждого этапа и конкретными измеримыми критериями успеха и провала.

АРХИТЕКТУРА

Аналитическое решение - детерминированный пайплайн, работающий без LLM и обеспечивающий базовую функциональность для основы будущих размышлений LLM:
    Анализ таблиц хвостов (manual-analysis). Excel-файлы с данными флотации парсятся по структурным правилам: определяются колонки с металлами по заголовкам (Содержание/Извлечение, % и т), извлекаются строки-категории по ключевым словам (Силикатная форма/Валлериит, Примесь в пирротине, Пирит), агрегируются данные по фракциям крупности (шламы -10 мкм vs крупные сростки +74 мкм) из секций «Итого (проверка)», оцениваются потери автоматизации как ~5% от суммы извлечённых. Результат - структурированный CSV/JSON в формате шаблона tailings_analysis_input.csv.
    Гибридный режим: при доступности LLM-сервиса аналитический пайплайн дополняется нейросетевым анализом - Excel-данные передаются модели с промптом, содержащим правила маппинга категорий; модель возвращает JSON с извлечёнными статьями потерь. При ошибке или недоступности LLM - прозрачный fallback на детерминированный парсер.

Система построена на архитектуре RAG (Retrieval-Augmented Generation) с тремя LLM-агентами, работающими в цикле взаимной проверки: 

1. Agent 1 - Generator (DeepSeek V4). Получает запрос пользователя и релевантные чанки документов из векторной БД через гибридный поиск (BM25 + dense embeddings с Reciprocal Rank Fusion). Генерирует Top-N гипотез с формулировкой, механизмом влияния и ссылками на источники. Может вызывать VLM-модель Qwen 3.6 35B для анализа схем, диаграмм и изображений из документов.

2. Agent 2 - Actor / Validator (DeepSeek V4). Проверяет каждую гипотезу: ищет подтверждающие источники в базе знаний, Google Scholar и Arxiv, верифицирует корректность ссылок, формирует развёрнутое обоснование. Если не может устранить замечания Judge - отбрасывает гипотезу.

3. Agent 3 - Judge / Critic (DeepSeek V4). Критикует гипотезу: целенаправленно ищет контраргументы и противоречия в литературе. Оценивает гипотезу по пяти бинарным метрикам: полнота научного обоснования (вес 0.5), наличие всех ссылок на источники (блокирующая - без неё гипотеза отклоняется), описание механизма влияния и оценка новизны (вес 0.3), анализ технических и экономических рисков (блокирующая), ожидаемая ценность и влияние на KPI (вес 0.2). Цикл Actor <-> Judge продолжается до достижения пороговых значений всех метрик.

RAG-пайплайн: все входящие документы проходят предобработку - PDF, DOCX и XLSX конвертируются в Markdown, изображения (PNG/JPG) передаются VLM-модели для получения текстового описания, веб-страницы рендерятся через headless Chromium (Playwright) и очищаются алгоритмом Readability. LossForm bucket-ы из Excel несут тонны, recoverable и привязку к ячейке. Чанки индексируются в Qdrant: BM25 + dense embeddings, fusion через weighted RRF, graph-overlap rerank и MMR (диверсификация дублей из литературы). На retrieval - provenance: citation с page/§/excel cell и highlight overlap.

Граф знаний: онтология обогащения (Factory -> LossForm -> Mineral/Metal -> Mechanism -> Process -> Equipment) собирается из Excel и wiring-каталога; PDF линкуется keyword linker-ом (EVIDENCED_BY), не «NER по всему корпусу». Граф - Neo4j / networkx. GraphRAG стартует от LossForm bucket, обходит граф 2–3 hop по Swanson ABC (форма -> механизм -> интервенция), фильтрует оборудование по constraints фабрики, подмешивает budget/regulation chunks. Graph + hybrid + constraints -> RRF -> rerank -> abc_evidence + top-k чанков; поддержка multi-hypothesis (несколько перефраз от LLM -> fused evidence per ветка).

ФРОНТЕНД

Одностраничное приложение на React 19 + TypeScript 6 с чат-интерфейсом. Пользователь загружает документы через drag-and-drop или по URL (с автоматической экстракцией контента и визуальным прогресс-баром). Чат поддерживает потоковый вывод (SSE) - пользователь видит генерацию в реальном времени. Панель превью документа имеет три вкладки: «Инфо» (метаданные), «Контент» (рендеринг Markdown с поддержкой кода, таблиц, формул), «Файл» (просмотр PDF/изображений). Дорожная карта отображается как вертикальный таймлайн с этапами, ресурсами и критериями. Интерфейс выполнен в стиле glassmorphism с тёмной темой, ресайзабельными панелями и персистентностью данных между сессиями.

МОДЕЛИ И ИНФРАСТРУКТУРА

Используются две модели через Yandex AI Studio API: Qwen 3.6 35B как VLM (Vision Language Model) для анализа изображений, схем и диаграмм. DeepSeek V4 применяется для трёх агентов генерации и валидации гипотез. Все модели поддерживают русский, английский и китайский языки.

Система разворачивается через Docker Compose одной командой. Nginx выступает API Gateway: проксирует запросы к LLM-сервису (порт 8000) и сервису экстракции контента (порт 8005), отключает буферизацию для стриминга. Локальное развёртывание гарантирует, что конфиденциальные данные предприятия не покидают внутренний контур. Архитектура позволяет подключать новые предметные области (полимеры, композиты, катализаторы) без перестройки ядра - через конфигурацию графа знаний и доменных онтологий.

Фабрика гипотез - интеллектуальная система генерации научно-исследовательских гипотез для НИИ и промышленных лабораторий в области материаловедения и металлургии.

Проблема: на старте R&D-проектов гипотезы формируются вручную и зависят от опыта отдельных экспертов. Это субъективно, медленно и не использует накопленные данные - отчёты, лабораторные журналы и патенты лежат мёртвым грузом. Нет единого формата для сравнения гипотез по новизне, рискам и ресурсам. Недели уходят на формулировку и согласование направлений.

Решение: пользователь вводит описание технологической проблемы, ограничения (сырьё, бюджет, оборудование) и загружает документы (статьи, патенты, отчёты, URL). Система генерирует структурированный список гипотез. Для каждой - научное обоснование, ссылки на источники, оценка новизны, карта рисков и ожидаемое влияние на KPI. Опционально - дорожная карта проверки с последовательностью экспериментов, ресурсами, сроками и измеримыми критериями успеха и провала.

Ядро системы - три LLM-агента на базе DeepSeek V4, работающих в цикле взаимной проверки. Generator генерирует гипотезы на основе запроса и релевантных чанков из базы знаний. Actor проверяет каждую гипотезу: ищет подтверждающие источники, верифицирует ссылки, формирует обоснование. Judge критикует гипотезу по пяти метрикам (полнота обоснования, наличие ссылок, механизм влияния, риски, ценность) и либо возвращает на доработку, либо утверждает. Цикл повторяется до достижения пороговых значений. VLM-модель Qwen 3.6 35B анализирует схемы и изображения из документов.

Поиск - гибридный: BM25 по ключевым словам и dense embeddings для семантического поиска, результаты объединяются и реранжируются. Граф знаний на Neo4j связывает сущности (материалы, свойства, процессы, оборудование) и позволяет находить неочевидные аналогии между разными областями. Все документы проходят предобработку: PDF, DOCX, XLSX конвертируются в Markdown, веб-страницы рендерятся через Chromium и очищаются алгоритмом Readability. Система разворачивается через Docker Compose, работает локально - данные не покидают контур предприятия.
