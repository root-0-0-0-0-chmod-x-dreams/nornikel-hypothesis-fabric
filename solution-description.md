# Фабрика гипотез — описание решения

## 1. Аннотация

**Фабрика гипотез** — интеллектуальная система для генерации, приоритизации и планирования проверки научно-исследовательских гипотез в области материаловедения и металлургии. Система принимает на вход описание технологической проблемы, ограничения и набор документов (статьи, патенты, отчёты, URL), а на выходе формирует структурированный список проверяемых гипотез с научным обоснованием, ссылками на источники, оценкой рисков и дорожной картой верификации.

Решение построено на архитектуре RAG (Retrieval-Augmented Generation) с тремя LLM-агентами — Генератор, Критик и Валидатор — работающими в цикле взаимной проверки для обеспечения качества и обоснованности гипотез. Пользовательский интерфейс выполнен в виде одностраничного веб-приложения с чат-интерфейсом, загрузкой документов и визуализацией дорожных карт.

Система разворачивается через Docker Compose, поддерживает работу с конфиденциальными данными в локальном контуре и масштабируется на новые предметные области без перестройки ядра.

---

## 2. Проблематика

На старте научно-исследовательских проектов в НИИ и промышленных лабораториях отсутствует системный механизм генерации и приоритизации гипотез. Это приводит к следующим проблемам:

1. **Субъективность и зависимость от экспертов.** Идеи формируются вручную, опираясь на опыт отдельных сотрудников. Это снижает воспроизводимость, создаёт «узкие места» и делает процесс неустойчивым к уходу ключевых специалистов.

2. **Низкая связность с бизнес-частью.** Предлагаемые гипотезы не всегда сопровождаются проработкой бизнес-эффекта. В результате перспективные направления игнорируются, а ресурсы тратятся на дублирование известных решений.

3. **Неэффективное использование исторических данных.** Накопленные отчёты, лабораторные журналы и результаты экспериментов остаются в виде неструктурированных архивов и не используются для генерации новых идей.

4. **Отсутствие прозрачной оценки.** Нет единого формата обоснования гипотез. Сложно сравнить варианты по новизне, рискам, требуемым ресурсам и ожидаемой ценности.

5. **Замедление старта проектов.** Время на формулировку и согласование исследовательских направлений растягивается на недели, что снижает общую скорость инновационного цикла.

## 3. Архитектура решения

### 3.1. Общая схема

Система состоит из пяти основных подсистем:

```
Пользователь → Frontend → API Gateway (nginx) → LLM Service (YandexGPT)
                                   ↓
                            Content Extraction (Playwright + Readability)
                                   ↓
                            Data Pipeline (PDF/Word/Excel → Markdown → Chunks)
                                   ↓
                            Vector DB + GraphRAG (Neo4j / Qdrant, BM25 + embeddings)
                                   ↓
                            LLM Agents (DeepSeek): Generator → Actor ↔ Judge
```

### 3.2. Подсистемы

| Подсистема | Назначение | Технологии |
|---|---|---|
| **Frontend** | Пользовательский интерфейс: чат, загрузка документов, превью, визуализация дорожных карт | React 19, TypeScript 6, Tailwind CSS v4, Vite |
| **LLM Service** | API-шлюз к языковым моделям: чат, генерация гипотез, SSE-стриминг | FastAPI (Python 3.11), YandexGPT, Alice LLM, Qwen 3.6 35B (VLM) |
| **Content Extraction** | Извлечение очищенного контента из веб-страниц: рендеринг Chromium → Readability → Markdown | FastAPI (Python 3.12), Playwright, readability-lxml, markdownify |
| **Data Pipeline** | Предобработка документов: PDF/Word/Excel → Markdown, чанкинг, извлечение метаданных | openpyxl, pandas, docx2md, opendataloader |
| **RAG + Agents** | Гибридный поиск (BM25 + embeddings), граф знаний, три LLM-агента для генерации и валидации гипотез | Neo4j, Qdrant, DeepSeek API, LangChain |

### 3.3. Три агента — цикл генерации и проверки

1. **Agent 1 — Generator (DeepSeek)**
   - Принимает запрос пользователя + релевантные чанки из векторной БД
   - Генерирует Top-N гипотез
   - Для каждой гипотезы: формулировка, механизм, источники
   - Может вызывать VLM (Qwen 3.6 35B) для анализа схем и изображений

2. **Agent 2 — Actor / Validator (DeepSeek)**
   - Проверяет гипотезу: поиск подтверждающих источников (БД, Google Scholar, Arxiv)
   - Проверяет корректность ссылок
   - Формирует обоснование
   - Если не может исправить замечания Judge — отбрасывает гипотезу

3. **Agent 3 — Judge / Critic (DeepSeek)**
   - Критикует гипотезу: поиск контраргументов
   - Оценивает по бинарным метрикам:
     - Полнота обоснования (вес 0.5)
     - Наличие всех ссылок (блокирующая)
     - Механизм влияния + новизна (вес 0.3)
     - Оценка рисков (блокирующая)
     - Ожидаемая ценность / KPI (вес 0.2)
   - Возвращает гипотезу Actor'у на доработку или принимает

Цикл Actor ↔ Judge продолжается до достижения пороговых значений метрик.

### 3.4. RAG и поиск

- **Гибридный поиск:** BM25 (разреженный) + dense embeddings (плотный) → Reciprocal Rank Fusion
- **GraphRAG:** обход графа сущностей на 2-3 шага, извлечение путей и связанных узлов
- **Метаданные чанка:** Summary, вопросы для поиска, заголовок, подзаголовок, источник

## 4. Функциональные возможности (MVP)

### 4.1. Интерфейс пользователя

- **Чат с LLM:** текстовые запросы, поддержка изображений (VLM), потоковый вывод (SSE)
- **Загрузка документов:**
  - Drag-and-drop файлов (PDF, DOCX, XLSX, PNG, JPG)
  - Загрузка по URL с автоматической экстракцией контента
  - Визуальный прогресс-бар с процентами
- **Превью документов:**
  - Вкладка «Инфо»: метаданные, размер, тип, дата, источник
  - Вкладка «Контент»: рендеринг Markdown с поддержкой кода, таблиц и ссылок
  - Вкладка «Файл»: просмотр PDF и изображений через iframe
- **Дорожная карта:** вертикальный таймлайн с этапами проверки гипотезы, ресурсами, сроками и критериями успеха/провала
- **Тёмная тема:** переключатель с сохранением выбора
- **Ресайз панелей:** сайдбар и панель превью растягиваются (до 35% и 45% ширины экрана)
- **Persistence:** документы и извлечённый контент сохраняются между сессиями (localStorage)

### 4.2. API

| Метод | Путь | Назначение | Готовность |
|---|---|---|---|
| `POST` | `/api/v1/chat` | Чат с LLM (текст + изображения) | ✅ |
| `POST` | `/api/v1/chat/stream` | Потоковый чат (SSE) | ✅ |
| `POST` | `/api/v1/hypotheses/generate` | Генерация гипотез | Спроектирован |
| `POST` | `/api/v1/hypotheses/generate/stream` | Потоковая генерация | Спроектирован |
| `POST` | `/api/v1/hypotheses/{id}/roadmap` | Дорожная карта проверки | Спроектирован |
| `POST` | `/api/v1/hypotheses/{id}/feedback` | Обратная связь эксперта | Спроектирован |
| `GET`  | `/api/v1/history` | История гипотез с фильтрацией | Спроектирован |
| `POST` | `/api/v1/extract` | Экстракция контента из URL | ✅ |

Полная спецификация: `api-spec.json`

### 4.3. Поддерживаемые форматы и языки

- **Входные форматы:** текст, PDF, DOCX, XLSX, PNG, JPG, URL (HTML)
- **Языки:** русский, английский, китайский (модели YandexGPT и Qwen)
- **Выходные форматы:** JSON (API), Markdown (контент), планы на PDF/DOCX/CSV

## 5. Технические детали

### 5.1. Стек технологий

| Слой | Технологии |
|---|---|
| Frontend | React 19, TypeScript 6.0, Tailwind CSS v4, Vite 8, Lucide Icons, react-markdown + remark-gfm |
| Backend (LLM) | FastAPI (Python 3.11), OpenAI SDK (Yandex-совместимый), uvicorn, asyncio |
| Backend (Extraction) | FastAPI (Python 3.12), Playwright + Chromium, readability-lxml, BeautifulSoup4, markdownify |
| Модели | YandexGPT (текст), Alice LLM (чат), Qwen 3.6 35B (VLM — изображения/схемы) |
| Инфраструктура | Docker Compose, nginx (SPA + reverse proxy), SSE streaming |

### 5.2. Развёртывание

```bash
git clone <repo>
cd nornikel-hypothesis-fabric
cp llm-service/.env.example llm-service/.env
# Заполнить: YANDEX_API_KEY, YANDEX_FOLDER_ID
docker compose up --build
```

После запуска:
- **Frontend:** http://localhost (nginx, порт 80)
- **LLM Service:** http://localhost:8000/docs (Swagger)
- **Content Extraction:** http://localhost:8005/docs (Swagger)

### 5.3. Ключевые архитектурные решения

- **Всё в Docker:** единый `docker-compose.yml` поднимает фронт, LLM-сервис и сервис экстракции
- **nginx как API Gateway:** проксирует `/api/v1/chat*` → LLM, `/api/v1/extract` → Extraction, отключает буферизацию для SSE
- **SSE для стриминга:** ответы от LLM приходят потоком, пользователь видит генерацию в реальном времени
- **Glassmorphism UI:** полупрозрачные панели с backdrop-blur, градиентный фон, тени, тёмная тема
- **API-first:** полный контракт спроектирован до реализации бэкенда гипотез — фронт и бэк могут разрабатываться параллельно

## 6. Соответствие требованиям

| Требование | Реализация |
|---|---|
| **Полезность для исследователей** | Гипотезы конкретны, проверяемы, с лабораторными критериями успеха/провала |
| **Прозрачность и обоснованность** | Каждая гипотеза — rationale + источники + механизм; UI показывает всю цепочку |
| **Гибкость входных данных** | Текст, файлы (PDF/DOCX/XLSX/PNG), URL — парсятся и унифицируются в Markdown |
| **Масштабируемость** | Предметная область задаётся конфигурацией графа знаний, ядро не меняется |
| **Интеграция** | Docker Compose, API-first, планы на Jira/YouTrack и экспорт PDF/DOCX |
| **Интерпретируемость** | Три агента с бинарными метриками, пользователь видит rationale и источники |
| **Мультиязычность** | YandexGPT + Qwen поддерживают ru/en/zh |
| **Надёжность** | Обработка ошибок экстракции, fallback-модели, graceful degradation |
| **Производительность** | SSE-стриминг, генерация гипотез за минуты, не часы |
| **Безопасность** | Локальное развёртывание (Docker), конфиденциальные данные не покидают контур |

## 7. Дорожная карта развития

### Фаза 1 — MVP
- Frontend: чат, документы, превью, роадмапа
- LLM-сервис: YandexGPT, стриминг
- Content extraction: URL → Markdown
- Docker Compose, nginx

### Фаза 2 — Генерация гипотез (текущая)
- LLM Agent 1: генерация гипотез по запросу + документам
- RAG-поиск по загруженным документам
- Интеграция фронта с реальным API гипотез

### Фаза 3 — Валидация и граф знаний
- Agents 2/3: Actor + Judge для взаимной проверки
- Neo4j: граф материалов, свойств, процессов
- GraphRAG: обход графа + RRF fusion

### Фаза 4 — Продакшн
- Парсинг PDF/DOCX/XLSX → Markdown
- Web retrieval (Google Scholar, Arxiv, Роспатент)
- Экспорт отчётов (PDF, DOCX)
- Интеграция с Jira/YouTrack
- Аутентификация и ролевая модель

---

## 8. Заключение

«Фабрика гипотез» — это не просто чат-бот, а полноценная исследовательская платформа, которая:

- **Ускоряет старт R&D-проектов** с недель до минут
- **Повышает качество гипотез** за счёт цикла взаимной проверки (Actor ↔ Judge)
- **Использует накопленные знания** через RAG и графовый поиск
- **Обеспечивает прозрачность** — каждая гипотеза имеет измеримые критерии и источники
- **Масштабируется** на новые предметные области без перестройки ядра
- **Разворачивается локально** — конфиденциальные данные остаются в контуре предприятия

Система готова к пилотному внедрению в исследовательских лабораториях Норникеля и других промышленных компаний.
